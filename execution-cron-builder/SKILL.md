# Execution

For a first user-facing run, read `docs/getting-started.md` and
`docs/skill-selection.md`. This skill is a long-run execution protocol, not a
`b3ehive execution` CLI command.

core v2 · loop v1, default shape `single`. Read `references/core.md` and
`references/loop.md` first; this body adds only execution rules.

## Acceptance

- The master accepts an item after it integrates the submission into the
  canonical checkout, re-runs the item's `oracle.full` at the item's tier, and
  refreshes every status surface, the Gantt projection included.
- On failure the master rejects with notes. The next generation runs on another
  model family when one is available. Three failed generations: block the item,
  then replan it or open a compete run that scores repairs by the oracle.
- The controller generates two guards. Harvest refuses a submission that edits
  blueprint checkboxes or oracle paths. CI refuses a `[_] -> [x]` change unless
  a master commit carries the evidence row.
- Completion cleanup needs zero `[ ]`, zero `[_]`, no pending handoff,
  integration, or repair, and passing gates. A `persistent_pool` ends only on
  its frozen stop condition or an operator stop.

## Specification

Build the controller from this repository's evidence. Carry no controller,
constant, path, item prefix, route, count, or validator over from another
project. Freeze one versioned specification before install:

- blueprint path, parser, item-id rule, Gantt path
- runtime root, owned-path policy, workspace materialization
- submission and acceptance schemas, oracle commands, tiers, completion surfaces
- platform, substrate, route policy, lifecycle (`bounded` or `persistent_pool`),
  live target, hard cap, replacement policy
- nested-agent policy and caps for claims, executions, startups, transports,
  running turns, request starts, in-flight requests, integrations, validators
- scheduler cadence, leases, budgets, exact cron marker, skill version

An unknown field that could alter source, spend money, publish, or delete fails
closed with its name. Low-risk housekeeping defaults stay overridable and are
labeled as defaults. The controller carries the skill version and spec digest;
`b3ehive doctor` flags controllers generated by an older skill.

Inspect first: repository instructions, branch and dirty state, candidate
blueprints, build, test, lint, and benchmark entry points, generated and large
paths, host CPU, memory, disk, and accelerators, and existing crons, locks,
ledgers, and workers. Preserve user changes; reset, stash, checkout, and delete
stay off limits.

## Blueprint

One file holds requirements and the checklist:

```markdown
- [ ] [ID] title
  - depends_on: [ID, other#ID]
  - owned_paths: src/x/, verify/gates/ID.sh
  - oracle: verify/gates/ID.sh
  - tier: T1
  - budget: loc<5000
  - canon: [A2]
```

- `oracle` is required; an item without one gets a parent item that builds it.
- `other#ID` points into another blueprint and blocks acceptance, not work.
- Reject duplicate ids, missing dependencies, cycles, unknown marks, and chains
  inferred from document order. When layers exist, close lower layers first.
- Split an item whose estimate exceeds its budget before anyone claims it.
- Regenerate the read-only same-name Gantt projection
  (`<name>_Blueprint.<ext>` → `<name>_Gantt.<ext>`) every tick and never parse
  it back. Rules: `references/execution-pattern.md` §2.

## Claims And Workspaces

- Each claim owns a task root, an immutable claim card, and a fresh run id.
- Materialize declared writable paths and justified read-only files. A full
  repository copy per claim needs a `DECIDE` line showing the oracle needs it.
- Workers submit repository-relative patches with checksums and a receipt; the
  canonical checkout stays outside their reach.
- Harvest valid submissions into immutable queue storage before pruning any
  stale claim.
- Check ownership, inode independence, card digest, and changed paths at launch
  and at harvest.

## Item Loop

- Each item runs a loop. Decide `relay` or `review` for an item whose single
  attempts stall or whose oracle is weak.
- Repair is a new generation in a fresh run root; it never overlaps the
  generation it replaces.

## Workers And Transport

Transport-agnostic invariants:

- One worker generation owns one process tree, one private state home, one
  session, and one task root.
- Each model request needs an atomic request lease before submission; an
  execution holds at most one outstanding request.
- Liveness needs exact identity: process and start time, cwd, private state,
  route, session, and goal.
- Lifecycle is frozen. A `bounded` result ends its transport. A
  `persistent_pool` keeps a live generation until stop or proved death, then
  replaces it without exceeding the cap.
- Nested agents run only when the specification admits them, and each child
  counts against every cap.
- A request storm or an unauthorized continuation opens a fail-closed breaker;
  only an audited operator reset closes it.

Codex workers follow `references/transport-codex-tui.md` in full. Other runners
follow `references/substrate-cron.md`.

## Admission

- Keep separate caps for claims, executions, startups, live transports, running
  turns, request starts per window, in-flight requests, integrations, validator
  leases, and path conflicts.
- Check CPU, memory, swap, PIDs, disk, provider limits, and validator capacity
  before each launch.
- Inside one tick, launch waves until the live target is full, the tick budget
  ends, or a named limit binds. Persist the binding reason for every empty slot.
- Report claims, startups, transports, running turns, request rate, in-flight
  requests, breaker state, handoffs, and backlog as separate numbers.

Detail: `references/execution-pattern.md` §6.

## Scheduler Tick

1. Take the scheduler lease; validate the specification and transport.
2. Harvest submissions; reconcile dead, finished, and mismatched claims.
3. Validate the DAG; regenerate status and Gantt.
4. Integrate a bounded, conflict-safe, dependency-ready batch.
5. Reserve claims; release the lease and close lock descriptors before launch.
6. Launch waves outside the lease; replace proved-dead persistent generations.
7. Retake the lease briefly; merge outcomes; write status and Gantt atomically.

Model turns, builds, tests, and network calls never run under the lease.

## Substrate

Decide one substrate per run: `in-session` (subagents or a workflow tool),
`cron+tmux`, or `flow` (an external agent-flow runner). Cron, tmux,
runner templates, and disk guards: `references/substrate-cron.md`.

## Generated Validation

The controller ships tests showing that validate-only launches nothing; each
submission happens exactly once; claims stay isolated; caps stop lane `N+1` and
request `R+1`; harvest precedes prune; workers inherit no lock; the checkbox and
oracle guards hold; persistent replacement restores exactly the target; the
Gantt covers every id and stays fresh; cleanup touches only its own runtime; and
two unlike fixture repositories share no constants. Full list:
`references/gate-rules.md`.
